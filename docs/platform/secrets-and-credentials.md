# Secrets and Credentials

> **Status: stub.** Scope is agreed; rules are not yet written. Not normative until this notice is removed.

Defines how secrets and credentials are stored, accessed, and rotated. The standing rule already in force: no secrets in code, notebooks, or docs. Docs must never contain real hostnames, tokens, or workspace IDs.

## Scope (planned)

- Secret storage: Azure Key Vault-backed secret scopes as the default
- Access control on scopes and vaults; least privilege
- Rotation and expiration policy
- Integration patterns for pipelines, jobs, and apps (see [Service principal authentication](service-principal-auth.md))
