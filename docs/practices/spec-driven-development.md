# Spec-driven Development

> **Status: stub.** Scope is agreed; rules are not yet written. Not normative until this notice is removed.

Platform work starts from a spec, not from code. A spec states requirements, data contracts, acceptance criteria, and a validation plan before implementation begins. For datasets, the contract elements are defined in [Analytical dataset language](analytical-dataset-language.md); the acceptance check is the pivot test.

## Scope (planned)

- Requirement capture: the decision or workflow the work serves (see [BI practices guidance](bi-practices-guidance.md) for decision-first design)
- Data contract definition: period, grain, dimensions, measures, metrics
- Design review and acceptance criteria
- Testing and deployment validation; what "done" means
